# Use IronGraph as an AI second brain

Connect an MCP-capable AI host to IronGraph so it can query the graph, preserve durable context,
save complete documents, retrieve documents by meaning, and read the exact IronGraph Cypher
reference before composing unfamiliar statements.

The MCP server supports local stdio and loopback-only Streamable HTTP. Both transports connect to
IronGraph through the same Query API used by the supported clients, so neither creates another graph
data endpoint or storage path. A remote Query API connection requires mutual TLS.

## Prerequisites

- A running IronGraph instance
- The `irongraph-mcp` executable supplied with your IronGraph distribution
- An MCP host that supports stdio or Streamable HTTP servers
- At least one explicit IronGraph project; there is no implicit default project

## Connect a local host

Add this server entry to your MCP host configuration:

```json
{
  "mcpServers": {
    "irongraph": {
      "command": "irongraph-mcp",
      "args": ["--url", "http://127.0.0.1:18484"]
    }
  }
}
```

Restart or reconnect the host, then ask it to list the IronGraph projects. The expected result is a
call to `irongraph_get_schema` with no project and a `SHOW PROJECTS` result. If the host writes a
Cypher statement without first discovering the project and schema, instruct it to follow the
IronGraph server guidance rather than guessing names.

## Connect a URL-based local host

IronGraph starts its Streamable HTTP MCP listener at `http://127.0.0.1:18488/mcp`. Use this URL for
local hosts such as Unsloth Studio that add MCP servers by endpoint rather than by process command.
The listener rejects non-loopback binds and non-loopback browser origins.

When you launch the standalone executable directly with a custom Query API address, set
`IRONGRAPH_HTTP_ADDR` before starting it so Settings generates matching MCP host configurations.
If you use the `--http-addr` command option instead, also set `IRONGRAPH_MCP_URL` to that local
HTTP URL. The npm launcher carries the selected address into its MCP integrations automatically.

In Unsloth Studio, open **MCP**, choose **Add custom MCP**, and import the configuration generated by
IronGraph Settings. Test the connection, add the server, and enable both IronGraph and the **Use MCP
Servers** master control. The expected result is five discovered IronGraph tools.

## What the host receives

The MCP surface stays deliberately small:

| Tool | Use it for |
| --- | --- |
| `irongraph_run_cypher` | Every direct read, write, administration statement, graph algorithm, temporal query, and exact calculation over stored data |
| `irongraph_get_schema` | Listing projects or reading a project's live labels, relationship types, properties, functions, indexes, and schema revision |
| `irongraph_save_document` | Creating or updating a canonical `:Document` node with complete source text |
| `irongraph_search` | Semantic retrieval over any indexed node label, optionally including connected relationships and neighboring nodes |
| `irongraph_search_cypher_docs` | Finding the exact dialect page before writing unfamiliar IronGraph Cypher |

Cypher reads and writes share one tool. IronGraph parses and executes the statement through its
canonical query path; the host does not classify the operation or move stored data into a second
calculation system.

Every Cypher reference page is also available as an `irongraph://cypher/...` MCP resource. A host
can search the reference, read only the relevant page, and keep the large manual out of the normal
tool list.

## Prepare a durable document project

Create a project and defend the document identity before asking a host to save memory:

```cypher
CREATE PROJECT IF NOT EXISTS memory
```

```cypher
USE memory
CREATE (:Document {
  id: 'setup-document',
  title: 'IronGraph memory setup',
  body: 'This project stores durable context for AI hosts.',
  source: 'setup',
  embedding: [0.0]
})
```

```cypher
USE memory
CREATE CONSTRAINT document_id_unique
FOR (document:Document)
REQUIRE document.id IS UNIQUE
```

The host can now call `irongraph_save_document` with project `memory`. Supplying the same
`document_id` updates that document. Omitting it creates a new UUID. Document bodies remain ordinary
graph properties and follow the normal WAL and snapshot durability path.

## Enable semantic document recall

Declare the embedding index explicitly after at least one `Document` node has both `body` and
`embedding` properties:

```cypher
USE memory
CREATE EMBEDDING INDEX document_semantic
FOR (document:Document)
FROM document.body
INTO document.embedding
USING MODEL default
SIMILARITY COSINE
```

Check publication before search:

```cypher
USE memory
SHOW INDEXES
```

The expected row for `document_semantic` has state `ONLINE`. The host then calls
`irongraph_search` with project `memory`, index `document_semantic`, label `Document`, and the
natural-language meaning to retrieve. IronGraph encodes the phrase with the same verified local
model used by the index and returns complete matched nodes. By default, the result also includes
their connected relationships and neighboring nodes. Set `include_connections` to `false` when only
the ranked nodes and scores are needed.

The same tool works for any node label with a declared embedding index, such as `Person`, `Decision`,
`Event`, `Product`, or `Concept`. Embedding indexes rank nodes through a declared text property.
Relationship values enter the result through graph traversal from those matches; use
`irongraph_run_cypher` when you need to filter or rank relationship properties directly.

## Connect through remote mutual TLS

Use the remote HTTPS Query API and provide all three TLS files:

```json
{
  "mcpServers": {
    "irongraph": {
      "command": "irongraph-mcp",
      "args": [
        "--url", "https://database.example:18484",
        "--tls-cert", "/secure/client.crt",
        "--tls-key", "/secure/client.key",
        "--tls-ca", "/secure/server-ca.crt"
      ]
    }
  }
}
```

IronGraph requires TLS 1.3, a client identity trusted by the instance, and a server certificate
rooted in the supplied CA. Do not place certificate contents, private keys, or access credentials in
graph properties, MCP tool arguments, query results, or documents.

## Operational boundaries

- The stdio MCP process must be able to reach the running IronGraph instance. The local Streamable
  HTTP listener starts and stops with the IronGraph database process.
- Query output is bounded for host safety. A truncated result says so explicitly; narrow the Cypher
  or raise the tool's bounded row limit instead of treating a partial result as complete.
- The host must confirm destructive statements such as `DROP`, `CLEAR`, `PURGE`, and `DELETE` before
  calling the unified Cypher tool.
- MCP uses one selected IronGraph instance. Each Cypher operation still names its project explicitly.
- Semantic search requires a declared, `ONLINE` embedding index. The MCP server never guesses or
  silently creates one.
